# FortiStack Project Roadmap

## Infrastructure & Production Readiness

### 1. Data Persistence
- [ ] **Database**: Migrate from local Docker volume to managed PostgreSQL (RDS/Aurora) for production.
- [ ] **File Storage**: Migrate report storage from local filesystem (`/app/reports`) to object storage (AWS S3, Google Cloud Storage).
  - *Why*: In a containerized environment (ECS/K8s), local disk is ephemeral. Reports generated by a worker node must be accessible by the API node, which might be on a different server. S3 solves this.
  - *Plan*:
    1. Update `PDFGenerator` to upload to S3 after generation.
    2. Store the S3 URL (or key) in the database `reports` table.
    3. Update `Download` handler to either redirect to a pre-signed S3 URL (better for performance) or proxy the file stream (better for access control if not using pre-signed URLs).

### 2. Security
- [ ] **Secrets Management**: Move secrets from `.env` to AWS Secrets Manager or HashiCorp Vault.
- [ ] **CORS**: Tighten CORS policy to allow only the specific production frontend domain.
- [ ] **Rate Limiting**: Tune rate limits based on expected traffic.

### 3. Scalability
- [ ] **Worker Queues**: Currently, report generation runs in a goroutine or basic cron. For high scale, implement a robust task queue (e.g., Redis/Asynq) to handle report generation jobs reliably, retries, and dead-letter queues.
